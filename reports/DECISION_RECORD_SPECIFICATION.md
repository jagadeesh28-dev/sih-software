## 1. Executive Purpose & Governance Architecture

The Marine Operator Decision Record system provides deterministic, tamper-evident audit packages for voyage planning, speed optimization, and fleet dispatch decisions generated by EGREEN QUANTA.

Under contemporary maritime compliance regimes (such as EU MRV, FuelEU Maritime, and company Safety Management Systems under the ISM Code), algorithmic recommendations cannot operate as autonomous dispatch commands. A licensed marine superintendent or master must evaluate recommendations against actual navigational constraints, weather advisories, and commercial obligations.

To bridge machine learning/quantum-inspired optimization and regulatory auditability, EGREEN QUANTA implements a **four-stage state machine**:

```
[ DRAFT ] ──> [ REVIEWED ] ──> [ CONFIRMED ] ──> [ EXPORTED ]
   │                │                 │                  │
   ▼                ▼                 ▼                  ▼
Advisory       Superintendent     Licensed Officer    Cryptographic
Generated      Sanity-Checked     Sign-Off & Log      SHA-256 Package
```

1. **DRAFT**: Automated solver solution produced by Quantum-Inspired Evolutionary Algorithm (QIEA), Quantum Particle Swarm Optimization (QPSO), or NSGA-II.
2. **REVIEWED**: Superintendent or technical operator has inspected Pareto tradeoffs, fuel scenario projections, and feasibility metrics.
3. **CONFIRMED**: Licensed Master/Chief Engineer/Fleet Director has confirmed or overridden operational parameters (speed, fuel type, route adjustments).
4. **EXPORTED**: Self-describing, cryptographically sealed archive generated with canonical JSON, 20-column CSV derivative, calculation summary, and SHA-256 manifest.

## 2. Canonical JSON Schema Specification (`schemas/decision_record.schema.json`)

The canonical schema is defined using **JSON Schema Draft 2020-12** (`$schema: "https://json-schema.org/draft/2020-12/schema"`). It enforces `additionalProperties: false` across all root and sub-object definitions to guarantee zero unmodeled schema drift.

### 2.1 Schema Root Structure

| Section | Type | Description | Mandatory Fields |
|---|---|---|---|
| `record_metadata` | `object` | Identity, timestamps, and software provenance | `record_id`, `record_uuid`, `timestamp_utc`, `schema_version`, `system_identity`, `software_version`, `git_commit`, `environment` |
| `input_snapshot` | `object` | Complete operating environment and constraints | `vessel_id`, `vessel_name`, `vessel_type`, `deadweight_tonnes`, `design_speed_knots`, `speed_through_water_knots`, `draft_mid_m`, `displacement_tonnes`, `cargo_tonnes`, `origin_port`, `destination_port`, `distance_nm`, `weather` |
| `prediction` | `object` | Fuel consumption inference and uncertainty bounds | `fuel_consumption_rate_kg_h`, `predicted_total_fuel_tonnes`, `prediction_interval_95`, `model_type`, `model_version`, `uncertainty_method`, `ood_metrics`, `fallback_invoked` |
| `scenario` | `object` | Fuel blend, calorific value, and lifecycle emissions | `fuel_type`, `fuel_category`, `blend_ratio`, `lower_calorific_value_mj_kg`, `wtt_ghg_factor_gco2e_mj`, `ttw_ghg_factor_gco2e_mj`, `lifecycle_ghg_tonnes`, `fuel_cost_usd_per_tonne`, `total_fuel_cost_usd`, `compliance_frameworks` |
| `objectives` | `object` | Multiobjective criteria evaluated by optimizer | `total_fuel_consumption_tonnes`, `total_operational_cost_usd`, `total_lifecycle_ghg_tonnes`, `schedule_delay_hours`, `port_dwell_time_hours` |
| `constraints` | `object` | Navigation, machinery, and regulatory safety margins | `all_hard_constraints_satisfied`, `hard_constraint_count`, `hard_violations`, `soft_penalties`, `speed_window_knots`, `eta_deadline_utc`, `eta_projected_utc`, `cii_rating_predicted` |
| `optimization` | `object` | Algorithm, seed, convergence, and execution metrics | `algorithm`, `random_seed`, `evaluation_budget`, `evaluations_completed`, `execution_time_seconds`, `pareto_rank`, `solution_id`, `hyperparameters` |
| `decision` | `object` | Operator sign-off, role, rationale, and overrides | `operator_id`, `operator_name`, `operator_role`, `decision_status`, `timestamp_utc`, `review_notes`, `approved_speed_knots`, `speed_override_reason`, `fuel_type_override`, `checklist_verified` |

| `integrity` | `object` | Cryptographic seal and verification pointers | `canonical_hash_algorithm`, `record_sha256`, `manifest_reference`, `tamper_evident` |

### 2.2 Section-by-Section Engineering Details

#### A. `record_metadata`
- `record_id`: Formatted string `REC-OPT-[0-9a-f]{8}` or `REC-SCEN-[0-9a-f]{8}`.
- `schema_version`: Strict SemVer `"1.0.0"`.
- `git_commit`: Active git HEAD commit (`e28472b...`).

#### B. `input_snapshot`
- Captures physical vessel hydrodynamics: `speed_through_water_knots`, `draft_mid_m`, `displacement_tonnes`, `cargo_tonnes`.
- Environmental snapshot includes `significant_wave_height_m`, `peak_wave_period_s`, `wave_direction_deg`, `wind_speed_m_s`, `wind_direction_deg`, `sea_surface_temp_c`, and `water_depth_m`.

#### C. `prediction`
- Evaluated via primary LightGBM regressor (`models/serving_lightgbm_production.pkl` or neural equivalent) or physics-informed fallback model (`src/models/physics_reference.py`).
- Uncertainty interval (`prediction_interval_95`): Includes `lower_bound_tonnes`, `point_estimate_tonnes`, `upper_bound_tonnes`, and `confidence_level: 0.95`.
- Out-of-Distribution (`ood_metrics`): Includes Mahalanobis distance / reconstruction error, threshold, and status (`INSIDE_ENVELOPE` or `OUT_OF_DISTRIBUTION`).
- Safe Fallback flag (`fallback_invoked`): Explicit boolean indicating whether hydrodynamic polynomial reference was used.

#### D. `scenario`
- Alternative fuel parameters: MGO, VLSFO, LNG, B20_BIOFUEL, B100_BIODIESEL, E_METHANOL, GREEN_AMMONIA, LIQUID_H2.
- LCV (MJ/kg), WtT (Well-to-Tank), and TtW (Tank-to-Wake) emission factors aligned with IMO Resolution MEPC.391(81) and EU MRV.
- Carbon intensity rating (`cii_rating_predicted`): Estimated grade `A` through `E`.

#### E. `objectives` & `constraints`
- Tracks all four optimization goals simultaneously: Fuel (tonnes), Cost ($), Lifecycle GHG (tCO2e), Delay (hours).
- Hard constraint verification: Speed bounds, maximum draft, delivery window, machinery MCR limit.

#### F. `optimization`
- Documents deterministic seed, solver (`QIEA`, `QPSO`, `NSGA-II`), budget, elapsed time, and hyperparameter snapshot (rotation angle $\theta$, quantum register length, swarm acceleration coefficients).

#### G. `decision`
- Officer sign-off: Human-in-the-loop audit trail. Tracks `operator_id` (e.g. `OFFICER-7749`), `operator_role` (`MASTER`, `CHIEF_ENGINEER`, `FLEET_SUPERINTENDENT`), `decision_status` (`CONFIRMED`, `EXPORTED`, etc.), and speed override reasons.

#### H. `integrity`
- Canonical JSON serialization conforms to **RFC 8785** (JSON Canonicalization Scheme / JCS):
  - Keys sorted lexicographically by UTF-8 code point.
  - Zero redundant whitespace (separators `("," , ":")`).
  - Numbers formatted with standard IEEE 754 precision.
  - SHA-256 digest computed across the canonical byte sequence.

## 4. Self-Describing Export Package Layout

Export packages are stored under `exports/EGREEN_QUANTA_<record_id>/` and contain the following mandatory files:

```
exports/EGREEN_QUANTA_<record_id>/
├── manifest.json              # Cryptographic SHA-256 manifest of all package files
├── decision_record.json       # Full canonical JSON decision record
├── decision_record.csv        # 20-column tabular derivative
├── README.txt                 # Human-readable operator verification instructions
├── calculation_summary.json   # High-level KPIs, model metadata, and environment summary
└── pareto_front.csv           # Alternative Pareto trade-off options (if optimization)
```

### 4.1 Cryptographic Manifest Specification (`manifest.json`)
The manifest conforms to `schemas/manifest.schema.json` and records:
- `package_id`: `EGREEN_QUANTA_<record_id>`
- `record_id`: `REC-OPT-...` or `REC-SCEN-...`
- `created_utc`: Generation timestamp
- `files`: Object dictionary mapping relative filename to:
  - `sha256`: Hexadecimal SHA-256 hash of file contents
  - `size_bytes`: Integer file size
  - `mime_type`: MIME string (`application/json`, `text/csv`, `text/plain`)
- `verification`:
  - `algorithm`: `"SHA-256"`
  - `total_files`: Count of verified files
  - `manifest_sha256`: Self-integrity checksum of the sorted file digests

## 5. Third-Party Auditor Verification Protocol

An external classification auditor, port authority inspector, or flag state surveyor can verify package integrity with standard shell utilities:

```bash
# 1. Verify individual file digests against manifest.json
sha256sum decision_record.json decision_record.csv README.txt calculation_summary.json

# 2. Automated Python verification script
python -c "
import json, hashlib, sys
with open('manifest.json') as f:
    m = json.load(f)
for name, meta in m['files'].items():
    with open(name, 'rb') as f:
        digest = hashlib.sha256(f.read()).hexdigest()
    assert digest == meta['sha256'], f'TAMPER DETECTED: {name}'
print('VERIFICATION SUCCESS: All files match cryptographic manifest.')
"
```
